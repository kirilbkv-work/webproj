Annual Project — Web Programming Course

1. Общая цель проекта

Разработать прототип пользовательского интерфейса веб-приложения для цифрового магазина одежды. Проект направлен на демонстрацию навыков проектирования UI, навигации и моделирования backend-логики на уровне интерфейсов и сервисов.

Прототип не требует реального backend — вся логика данных должна быть смоделирована.

⸻

2. Тема проекта

Digital Clothing Store — веб-приложение для поиска, просмотра и бронирования предметов одежды.

⸻

3. Пользователи

Тип пользователя
	•	В приложении существует только один тип пользователя — Customer.

Профиль пользователя

Каждый пользователь имеет персональный профиль со следующими данными:
	•	Имя и фамилия
	•	Контактная информация:
	•	Email
	•	Телефон
	•	Адрес
	•	Избранные типы одежды
	•	Данные для входа в систему

Требования:
	•	Профиль можно редактировать
	•	Все данные вводятся при регистрации

⸻

4. Аутентификация

Доступ без авторизации
	•	Просмотр каталога товаров
	•	Чтение отзывов других пользователей

Требуется авторизация
	•	Резервирование (заказ) товаров
	•	Доступ к корзине (Order Cart)
	•	Управление заказами

Регистрация
	•	Пользователь обязан заполнить все поля профиля

⸻

5. Каталог товаров

Набор товаров
	•	Предопределённый список товаров
	•	Минимум 10 товаров, созданных заранее

Атрибуты товара (Item)

Для каждого товара должны отображаться:
	•	Название
	•	Тип (sportswear, workwear, formalwear и т.д.)
	•	Размер
	•	Производитель
	•	Дата выпуска
	•	Цена
	•	Отзывы пользователей, которые заказывали данный товар

⸻

6. Поиск товаров

Поиск осуществляется по предопределённому набору товаров.

Критерии поиска (каждый отдельно):
	•	Название
	•	Тип
	•	Размер
	•	Производитель
	•	Дата выпуска
	•	Диапазон цен
	•	Отзывы пользователей

⸻

7. Просмотр каталога

Пользователь может:
	•	Листать товары вручную
	•	Выбирать товары без использования поиска

⸻

8. Резервирование товаров

Процесс резервирования
	•	Пользователь резервирует товар из каталога
	•	Пользователь получает уведомление о резервировании
	•	Товар добавляется в Order Cart

⸻

9. Корзина (Order Cart)

Общие требования

Корзина должна:
	•	Содержать все зарезервированные товары
	•	Автоматически рассчитывать общую стоимость

Данные заказа

Каждый заказ содержит:
	•	Название товара
	•	Тип
	•	Размер
	•	Производитель
	•	Дата выпуска
	•	Цена
	•	Статус заказа
	•	Рейтинг (если применимо)

Статусы заказа
	•	arrived
	•	in progress
	•	canceled

⸻

10. Управление заказами

Разрешённые действия

Статус заказа	Действия
arrived	удалить заказ, поставить рейтинг
in progress	изменить данные заказа
canceled	изменить данные заказа


⸻

11. Рейтинги и отзывы

Требования к рейтингам
	•	Пользователь может оценивать только свои заказы
	•	Заказ должен иметь статус arrived

Отображение рейтингов
	•	Формат отображения — на усмотрение автора:
	•	символы
	•	текст
	•	комбинированный формат
	•	Рейтинг должен быть:
	•	хорошо заметен
	•	легко интерпретируем

⸻

12. Технические требования

Тип приложения
	•	Web client application prototype

Технологии
	•	Angular / AngularJS (в соответствии с курсом)
	•	TypeScript

Backend-логика
	•	Симулируется через:
	•	TypeScript interfaces
	•	Angular services
	•	Реализовать операции:
	•	чтение
	•	добавление
	•	редактирование
	•	удаление данных

⸻

13. Состав прототипа

Прототип должен включать:
	•	Макеты страниц и диалогов
	•	UI-контролы и их компоновку
	•	Навигацию между страницами
	•	Открытие / закрытие диалогов
	•	Имитацию работы backend-логики в рамках сессии

⸻

14. Устройство
	•	Прототип может быть реализован для:
	•	телефона
	•	планшета
	•	ноутбука

⸻

15. Финальная сдача проекта

Обязательные материалы
	1.	Исходный код прототипа
	2.	PDF-документ со скриншотами интерфейса

Требования к PDF
	•	Один экран = одна страница
	•	Под каждым экраном:
	•	краткое описание функции экрана
	•	без описания визуального оформления

Пример описания:

Function: Search for items. Criteria for search are used as data about…
